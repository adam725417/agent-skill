# V2.1.1 修正說明｜Groq 400 reasoning_content

## 問題症狀

若使用 `openai/gpt-oss-20b` 搭配 Google ADK + LiteLLM + Tool Calling，
可能在第一次 Tool 回傳後的第二次模型呼叫看到：

`property 'reasoning_content' is unsupported`

這不是 API Key 錯誤，也不是 Python Tool 本身錯誤。

## 原因

GPT-OSS 在 Groq 上屬於 reasoning model。
ADK / LiteLLM 會把模型回傳的 reasoning 內容轉為歷史訊息的一部分；
後續 tool-result turn 再送回 Groq 時，特定組合可能把
`reasoning_content` 放進 assistant message，Groq Chat Completions
端點因此拒絕該 payload。

## V2.1.1 教學版處理方式

為了讓非程式背景學生上課時穩定：

```python
GROQ_MODEL = "groq/qwen/qwen3.8-27b"

model = LiteLlm(
    model=GROQ_MODEL,
    reasoning_effort="none",
)
```

Qwen 3.8 仍然支援 Tool Use，
但課堂關閉 reasoning，避免 reasoning history round-trip 問題。

## 為什麼不用在課堂上硬修 ADK / LiteLLM？

因為本課重點是：

- Agent
- Skill
- MCP
- Tool Calling
- LINE

而不是除錯不同 reasoning provider 的訊息格式差異。

正式專案若要重新開 reasoning，可在完成版本驗證後再進一步測試。
