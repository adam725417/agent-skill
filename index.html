Agent 核心觀念

AI Agent（人工智慧代理）與單次聊天最大的差異，是它可以在受控範圍內多步驟決策、呼叫工具，並根據結果繼續處理任務。

01 · REASON

接收任務與拆解需求

辨識客戶、料號、數量、交期，確認哪些資料還不足。

02 · ACT

選擇工具並取得事實

透過成本、歷史訂單、客戶資料工具補齊依據。

03 · VERIFY

核對規則，回傳可追溯結論

套用門檻規則並保留證據；超過權限轉交人工。

Agent 不等於「讓模型自由發揮」

成本、信用額度、交期與客戶資料不能臆測；重要報價應採最小權限、保留操作紀錄並在關鍵決策設人審。

MCP 模型上下文協定

MCP（Model Context Protocol）建立 MCP Client 與 MCP Server 溝通的標準介面；可讓 Agent 發現與使用 Tools、Resources、Prompts，而不必為每個資料來源打造完全不同的整合方式。

⇄

⇄
企業系統ERP / CRM / MES / CSV

Tools｜執行功能

查詢成本、取得工單、送出待審單；可能會改變系統狀態，必須控管權限。

Resources｜讀取內容

提供文件、設定、資料內容等上下文，實際支援範圍依 Server 而異。

Prompts｜工作模板

提供可重複使用的提示流程或參數化模板。

MCP / Skill 資源探索中心

從官方規格、Registry 到社群目錄；這些網站提供「尋找與研究」的起點，並不代表列出的所有第三方程式均安全或經官方認證。

搜尋路徑建議：先找官方原始碼或規格 → 查看維護者及更新紀錄 → 檢查授權和要求的權限 → 使用測試帳號或假資料驗證 → 才考慮上線。

企業使用 安全與治理

引進 MCP Server 與 Skill 不只是「能不能連上」，還必須確定資料、憑證、行為與稽核都在控制範圍內。

常見風險與處理方式

惡意指令 / Prompt Injection：外部文件與工具回應視為不可信內容，不得覆寫系統規則。

憑證洩漏：API Key 使用 Colab Secrets；不寫入 Notebook 或 Git。

過度權限：Tool 分開讀取與寫入，限制 OAuth 範圍與可操作資源。

供應鏈風險：審核第三方 Skill 腳本、套件來源與版本。

未授權決策：重要報價強制 REVIEW / 人工核准。
